Method v1.0 · November 2, 2026

Every assumption is visible.

The calculator uses decimal billions of parameters and converts bytes to binary GiB (1 GiB = 1,073,741,824 bytes). An actual GGUF file size overrides the estimated weight size. Runtime buffers and the system reserve are editable allowances.

weights = parameters × 1,000,000,000 × bits ÷ 8 × (1 + overhead / 100)
KV cache = 2 × layers × KV heads × head dimension × tokens × bytes × sequences
total GiB = (weights + KV cache) ÷ 1,073,741,824 + runtime GiB + reserve GiB

For grouped-query attention, use the number of key/value heads, not query heads. Each concurrent sequence gets its own full cache in this conservative calculation; weights are shared. Prefix sharing and paged allocation may reduce actual use. A static cache may allocate for the full configured context.

Do not apply this cache formula to MLA, recurrent or hybrid architectures without adjusting for their actual cache design. Multimodal encoders, adapters, speculative decoding and extra model copies are outside this calculation. Maximum context support, memory fit and generation speed are separate questions.

Memory planning questions

How much RAM does a 7B model need?

Weight precision and context change the answer. In this planner, a 7.61B model at 4 bits with 10% weight overhead uses about 3.90 GiB for weights. The Qwen2.5 7B example adds 0.44 GiB for an 8,192-token FP16 KV cache, plus your runtime allowance and system reserve. These are calculated estimates, not measured memory use.

Can I add system RAM and GPU VRAM together?

No. Choose the pool you intend to use. The GPU calculation budgets the full weights and KV cache in VRAM; system RAM must be available separately. Apple Silicon uses a shared pool, so leave room for macOS and other apps. Partial CPU/GPU offload requires a separate runtime-specific plan.

Does a 4-bit GGUF use exactly four bits per parameter?

No. Quantization blocks, scales, mixed-precision tensors and metadata add overhead. The default 10% is an editable planning allowance, not an exact Q4_K_M ratio. Enter the actual complete GGUF size to replace the parameter-based weight estimate.

Does this work for MoE, hybrid or multimodal models?

The weight estimate needs total resident parameters, including all resident MoE experts. The KV formula here is for conventional full-attention transformer layers, including grouped-query attention. It does not model MLA, recurrent state, hybrid/sliding-window allocation, vision encoders, speculative decoding or expert offload. Use runtime measurements for those architectures.

Are these hardware recommendations or benchmark results?

They are transparent planning calculations. Runtime buffers, cache allocation, fragmentation, backend versions and other apps can change actual memory use. The tool does not measure tokens per second or guarantee that a runtime can load a model. Verify the selected model and backend before buying hardware.

Can I share or cite a result?

Yes. Copy the result link to preserve every input or download the CSV with the formula version and settings. Cite LocalClaw, the calculator URL and your assumptions. No account or paid app is required.
