Need details?

Before you make it yours.

Is LocalClaw compatible with OpenClaw 2.0?
Yes. LocalClaw 1.0.203 supports OpenClaw 2026.8.2 and can safely migrate existing 2026.7.1 and 2026.8.1 installations. Update LocalClaw first, then use the app’s Updates screen to upgrade OpenClaw. See the 1.0.203 release notes for the details and upgrade checklist.
Does every OpenClaw 2.0 feature have a native LocalClaw screen?
No. LocalClaw provides native controls for its documented workflows, including setup, updates, models, Chat, Developer workspaces, agents, channels, cron jobs and Kanban. OpenClaw’s own features and interfaces depend on runtime version, provider, plugins and configuration. The launch’s interactive widgets, branching interfaces and experimental Swarm should not be read as a guarantee of equivalent native LocalClaw screens.
Do I need to pay for OpenClaw 2.0?
OpenClaw is free and open source. The $49 one-time price is for the optional native LocalClaw macOS app and its beta lifetime license. Cloud model providers, APIs and other third-party services can charge separately; they are not included in the LocalClaw license.
What should I back up before upgrading?
LocalClaw creates and verifies a runtime state backup before replacing OpenClaw. Its normal portable backup excludes project workspaces, so keep your own project backups as well. Review available disk space and follow the in-app checks. The retained 2026.7.1 runtime path does not mean a migrated database can always be downgraded.
What does beta lifetime access mean?
LocalClaw is available while it is still improving. The one-time $49 purchase gives you a lifetime license to the macOS app, with beta updates included and no recurring fee. Features and setup flows may change as the product matures.
What are the system requirements?
The current LocalClaw download is built for Apple Silicon Macs running macOS 13 Ventura or later. 8 GB RAM is the minimum; 16 GB or more is strongly recommended for practical local models. The models you can run depend on available memory and each model’s requirements. The current packaged build is not an Intel release.
Is the DMG notarized by Apple?
Yes. The current LocalClaw DMG is signed with a Developer ID certificate and notarized by Apple, so macOS Gatekeeper can verify it before launch. Notarization is Apple security scanning and ticketing; it is not App Store distribution or an Apple endorsement.
How does activation work?
After Stripe checkout, your license key is shown on the confirmation page. Download the installer, launch LocalClaw, enter your order email and license key, then activate. Activation uses a one-time internet check.
Is anything physically shipped?
No. LocalClaw is delivered digitally as an Apple-notarized macOS DMG. There is no physical shipping; the installer can be downloaded from the website and activated with the license key from checkout.
How do support and refund requests work?
LocalClaw is delivered as a digital beta license. If activation, download or installation fails, email helplocalclaw@gmail.com with the email used at checkout so the order can be verified and support can restore access. Refund requests are reviewed manually against the Stripe payment record and applicable consumer law; the website does not promise an automatic refund after digital access has been delivered.
Is the free model recommender still free?
Yes. The web recommender, model catalogue, TTS catalogue and hardware guides stay free. The $49 purchase is only for the optional native macOS app.
What if the install or license key has a problem?
Email support is included for activation, missing keys and install guidance. Use the same email address used during checkout so the order can be verified quickly.
Can I use local models, and what goes online?
LocalClaw supports local inference through LM Studio. Optional cloud and OAuth modes send requests to your chosen provider, and connected tools or channels can communicate with external services. Payment, license activation, downloads and updates require internet access. Data handling depends on the models, providers, tools and permissions you choose; a local runtime does not make every connected workflow offline.
